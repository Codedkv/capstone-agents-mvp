## 2. Memory MCP — infrastructure debt (NEW, not in STATE.md/CLAUDE.md)

### Diagnosis

Memory MCP server (`C:\Users\coded\mcp-servers\memory-mcp\dist\index.js`) crashed at **2026-05-07T18:50:12 UTC** with `Server transport closed unexpectedly`. No stderr in `mcp-server-memory.log` (file ends with `transport closed` and nothing else). Claude Desktop did not auto-restart — N-th consecutive crash threshold likely reached.

Manual stdin-less invocation of the server starts cleanly (banner `Memory MCP server running on stdio` appears in stderr). Code is healthy at startup. Crash is a runtime event during request processing.

Concurrent-clients hypothesis tested and rejected: second Chrome window has `memory` connector NOT enabled. Crash happened with single client.

### Most likely root cause

Unhandled promise rejection in async code paths (Voyage embeddings call or Supabase write). Memory MCP `src/index.ts` has no `process.on('uncaughtException')` / `process.on('unhandledRejection')` handlers, and tool handlers are not wrapped in try/catch with stderr logging. Errors die silently → process exits → log shows only `transport closed`.

### Recommended fix (kodder task)

```
TASK FOR CLAUDE CODE — patch C:\Users\coded\mcp-servers\memory-mcp\src\index.ts

Goal: when the memory MCP server crashes, the cause must appear in
%APPDATA%\Claude\logs\mcp-server-memory.log so future debugging is one log read.

Required changes (see existing src/index.ts for current structure):

1. Right after imports, register global error sinks:
   process.on('uncaughtException', (err) => {
     console.error('[FATAL uncaughtException]', err?.stack || err);
   });
   process.on('unhandledRejection', (reason) => {
     console.error('[FATAL unhandledRejection]', reason);
   });

2. Wrap each tool handler body in try/catch. In catch:
   console.error(`[TOOL ERROR] ${toolName}`, { args, err: err?.stack || err });
   then re-throw OR return an MCP error result, whichever matches existing pattern.

3. Add a low-noise heartbeat: every 10 minutes, console.error('[heartbeat] alive, uptime=Ns, mem=NMB').
   Use setInterval with .unref() so it does not block process exit.

4. Run `npm run build` to recompile dist/index.js.

5. Verify by causing a deliberate failure (e.g., temporarily make Voyage call throw) — ensure error appears in stderr and therefore in mcp-server-memory.log when run under Claude Desktop.

DO NOT touch tool logic, schemas, or Supabase calls. Pure observability layer.
Estimate: 20-30 minutes.
```

After kodder ships this, the next memory crash will reveal its cause in the log immediately.

### Phase 3 backend — known risks (need surfacing in STATE.md "Known limitations" section)

1. **In-memory state lost on uvicorn restart.** Active runs and event queues live in process memory. Restart kills any in-flight pipeline silently. Phase 6 deploy needs either Redis-backed state or systemd auto-restart with documented "restart kills runs" behavior.
2. **No cleanup of `runs/` directory.** Every analysis writes a new `runs/{uuid}/` folder, never deleted. Disk fills slowly. Phase 6 deploy needs a cron / cleanup endpoint deleting runs older than N days.
3. **Cancel is partial.** `/api/cancel/{id}` flips a flag checked between agents, not mid-LLM-call. UI already documents this, but worth adding to backend README too.

These risks should go into STATE.md `## 🐛 Known limitations` (currently lists analyzer + UI limitations; backend limitations missing).
